You are an expert full-stack software engineer, UX/UI designer, healthcare workflow architect, and AI product designer.

Build a production-ready web application called **CareFlow AI**.

CareFlow AI is an intelligent healthcare operations platform designed to improve patient access, prior authorization, and revenue cycle management. The platform should help healthcare staff, patients, and administrators reduce manual work, improve visibility, prevent delays, reduce claim denials, and improve the overall patient experience.

The application should feel calm, professional, trustworthy, and easy to read, especially for elderly users or users with low vision. Avoid flashy, overly futuristic, or generic AI-looking design. The interface should be simple, clean, warm, and healthcare-friendly.

---

## 1. Main Goal of the Application

Create a healthcare operations dashboard with AI-assisted workflows for:

1. **Patient Access**

   * Appointment scheduling
   * Insurance eligibility verification
   * Cost estimate support
   * Referral tracking
   * Patient reminders
   * No-show risk detection
   * After-hours support
   * Language and accessibility support

2. **Prior Authorization**

   * Check whether prior authorization is required
   * Collect needed clinical documentation
   * Compare patient/provider information with payer rules
   * Generate a prior authorization request draft
   * Detect missing documentation
   * Track authorization status
   * Display pending, approved, denied, and needs-review cases

3. **Revenue Cycle Management**

   * Claim review
   * Coding/documentation quality check
   * Denial risk prediction
   * Eligibility gap detection
   * Accounts receivable status
   * Patient payment support
   * Revenue leakage alerts

4. **AI Chatbot for Future Use**

   * Include a chatbot panel in the application
   * The chatbot does not need to be fully connected to real AI yet
   * Design it so it can later connect to OpenAI, Gemini, Claude, LangChain, RAG, MCP, or a healthcare knowledge base
   * The chatbot should support both patient-facing and staff-facing modes

## 11. Example User Flows

### Flow 1: Patient Books Appointment

1. Patient opens chatbot
2. Patient says they need an appointment
3. AI asks for reason, preferred time, and insurance
4. System suggests available appointment slots
5. Patient selects one
6. System checks insurance eligibility
7. System confirms appointment
8. Reminder is created

### Flow 2: Staff Reviews High No-Show Risk

1. Front desk opens Patient Access page
2. Filters by “High No-Show Risk”
3. Opens patient details
4. AI recommends reminder method
5. Staff sends reminder
6. Task is marked complete

### Flow 3: Prior Authorization Case

1. Staff opens Prior Authorization page
2. Selects a case marked “Missing Info”
3. AI shows missing documents
4. Staff uploads or checks documentation
5. AI generates prior authorization draft
6. Staff marks case as ready to submit

### Flow 4: Claim Denial Prevention

1. Billing staff opens Revenue Cycle page
2. Filters by “High Denial Risk”
3. Opens claim detail
4. AI explains why claim may be denied
5. Staff fixes documentation/coding issue
6. Claim status changes to “Ready to Submit”
